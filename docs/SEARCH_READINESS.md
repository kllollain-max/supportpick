## 현재 기준과 이미 완료된 구현

현재 확인 main·공개 sourceRevision은 `2654b39e464fa849afacbcc43585cf1fb6c07eab`이다. 승인 배포 `41820713647`의 실제 로그와 현재 공개 site-manifest.json을 함께 확인했다. 공개 자료 세대는 `gov24-41814036806-1`이며 로컬 초기 복구 ZIP의 세대와 구분한다. 이전 3개 URL/해시 상세만 제공하던 단계의 설명은 현재 상태에 적용하지 않는다.

- 자동 수집→완전성 검사→정적 상세/내부 링크/사이트맵 생성→전 URL 검사→승인 변수에 따른 배포→공개 revision/세대/해시/HTML 검사를 기존 독립 워크플로가 수행한다. 부분 수집과 오류는 마지막 정상 자료와 실패 상태를 보존한다. 기존 운영 설정을 이 후속 정비에서 변경하지 않는다.
- 콘텐츠 해시로 CSS·JS 캐시를 구분하는 PR #14와 일시적 전송 오류 1회 재검사도 기존 구현을 재사용한다. 현재 배포 실행은 HTML 11,057개가 최종 통과했고 초기 전송 오류 2개와 실제 복구가 로그에 남았다. 현재 버전 일치 확인 없이 이 수치를 다음 배포의 검사 결과로 재사용하지 않는다.

## Google Search Console

URL 접두어 속성 `https://kllollain-max.github.io/supportpick/`의 설정에서 **인증된 소유자**를 직접 확인했다. 실제 Google 태그는 search-verification.json에 있고 공개 생성 시 유지된다. 홈페이지 URL 검사에서는 **Google에 등록되어 있음**을 직접 확인했다. 개별 상세의 색인 여부는 URL별로 별도 확인한다.

정확한 `/supportpick/sitemap.xml` 제출 이력은 있지만 보고서는 여전히 ‘가져올 수 없음/사이트맵을 읽을 수 없음’, 발견 0이다. 현재 공개 XML은 HTTP 200·application/xml·UTF-8 파싱 성공·11,050개 고유 URL·경로 범위 정상이다. 홈페이지 색인은 사이트맵 처리 성공을 뜻하지 않는다. Google 내부 원인이 특정되지 않아 재처리 대기 가능성과 오류 미확정 상태를 구분하며, 변화 없는 제출·색인 요청을 반복하지 않는다.

## Naver·호스트 루트

실제 Naver 등록 화면은 `/careerpick/` 입력에 ‘URL을 호스트 단위로 입력해주세요.’라고 응답했다. 두 사이트는 같은 호스트 `https://kllollain-max.github.io`의 소유확인 범위에 포함될 수 있으며 프로젝트마다 별도 호스트인 것으로 중복 등록하지 않는다. 루트 소유확인 준비 화면에서 실제 발급 태그를 확보했으나 아직 공개 확인·등록·두 사이트맵 제출을 완료하지 않았다.

`robots.txt` 효력은 호스트 `/robots.txt` 기준이다. 현재 404 부재를 수집 차단으로 해석하지 않는다. 프로젝트 하위에 robots나 ads.txt를 만들어 호스트 처리를 완료했다고 보고하지 않는다. 루트 게시 후보와 실제 Naver·AdSense 태그는 CareerPick PR #19의 review-only/host-root에서 검토하며 승인 전에는 공개되지 않는다. 루트 게시/필요시 별도 저장소 생성은 별도 승인 단계다. 이 저장소는 커리어픽·루트·다른 프로젝트를 덮어쓰지 않는다. RSS는 현재 정적 상세와 사이트맵을 대신하는 필수 등록 조건으로 보지 않는다.

## AdSense 준비와 개인정보

동일 호스트의 기존 계정 사이트 상태는 ‘검토 필요’, ads.txt ‘찾을 수 없음’, 소유확인 미완료다. 지급 정보/사이트 연결 안내도 남아 있으며 본인·지급 정보는 운영자가 공식 화면에서 입력한다. 프로젝트 두 개를 이미 승인된 별도 광고 사이트라고 표현하지 않는다. Search Console 등록·사이트맵·실제 색인은 AdSense 신청의 필수 선행조건이 아니다.

현재 실제 광고/분석 SDK와 광고 요청은 없다. 초기 후보는 운영자가 읽고 승인한 해설이고, 개인 관리·저장·내 신청·빈 검색·오류·로딩·보류 문서는 제외한다. 같은 URL의 상태가 바뀌므로 URL 제외만으로 광고 상태 제어를 끝냈다고 판단하지 않는다. 광고 도입은 실제 동의·CMP/지역 조건·데이터 공개·계정 확인·명시 승인 뒤 별도 구현한다.

브라우저 기록은 supportpick 전용 키와 별도 백업/복구 형식을 유지한다. 운영자가 원격으로 기록을 열람·삭제하는 서버는 없다. 관심 해제/메모 변경·파일 삭제와 브라우저의 호스트 전체 데이터 삭제를 구분해 개인정보 안내를 보강했다. 호스트 전체 삭제는 커리어픽 기록도 지울 수 있어 먼저 두 서비스의 필요한 백업을 안내한다. 실제 개인 기록 삭제는 수행하지 않았다.

공식 API 이용권한과 첨부·사진·로고 등 제3자 자료 권리는 별개다. 공식 링크 하나만으로 재사용 허용이나 독자적 콘텐츠 가치가 보장되지 않는다. 신청 가능 여부·대상·금액의 전수 확인 또는 사람의 검수 완료를 주장하지 않는다.

## 검증·되돌리기·남은 승인

기존 tests/·tools/build.py·tools/verify_release.py와 공개 배포의 sourceRevision/세대/콘텐츠 해시를 재사용한다. 새 후속 수정의 CI·커밋·공개 적용 여부는 새 PR 결과로 별도 보고한다. 정책/해설 문구 변경만으로 새 수집이나 블로그/Threads 발행을 수행하지 않는다. 최신 정상 운영 세대 복원에 실패하면 초기 ZIP으로 조용히 배포하지 않는다.

루트 게시, 후속 PR 병합/배포, AdSense 심사·광고 활성화는 기존 승인 범위를 확인한 다음 해당 단계만 진행한다. 문제가 있으면 해당 변경만 revert하고 정상 아티팩트/최신 정상 자료로 복구한다. 개인 기록을 초기화하거나 운영 자료를 과거 ZIP으로 덮어쓰지 않는다. 기존 일일 검색 점검 예약을 재사용하고 중복 예약을 만들지 않는다.
