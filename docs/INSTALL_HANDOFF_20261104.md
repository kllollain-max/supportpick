# 지원금픽 홈 화면 설치 안내 보완

기준 main/공개 배포: `52d1744d4d1ec4655f0c3b1ed8583c4934ac2f88` (PR #20). 사용자 제공 화면은 Android Threads 내부에서 열린 지원금픽이며 기존 버튼은 수동 메뉴 안내만 표시했다. 설치 실패 여부나 휴대폰의 설치 완료 여부는 이 화면만으로 확정하지 않는다.

## 확인한 원인과 변경

공개 manifest·서비스워커·오프라인 안내·192/512 PNG 아이콘은 모두 HTTP 200이며 manifest MIME과 실제 아이콘 크기도 정상이다. 설치 파일을 다시 만들거나 앱 ID·start_url·scope를 바꾸지 않는다.

기존 안내에는 바로 브라우저로 이동하거나 주소를 복사하는 조작이 없어 사용자가 막혔다. 또 안내를 연 뒤 `beforeinstallprompt`가 도착해도 안내창에 설치 버튼이 나타나지 않았다.

- Android 안내에 사용자가 직접 누르는 ‘Chrome으로 열기’와 ‘설치 주소 복사’를 제공한다. 앱이 Intent를 차단하거나 Chrome이 없는 경우에도 주소 수동 복사와 앱 메뉴 안내를 이용할 수 있다. 외부 앱 열기를 타이머로 강제하지 않는다.
- Chrome 이동 주소는 공개 홈페이지 또는 해당 지원금 정규 주소만 사용한다. 검색 조건·신청 메모·임의 외부 URL을 넘기지 않는다. Chrome Intent에는 HTTPS fallback을 넣는다.
- `?install=1`은 사용자가 브라우저 이동을 선택한 뒤 안내를 이어가는 용도다. 도착 후 그 매개변수만 제거하고 기존 URL/방문 기록 상태를 보존한다. 설치 창을 자동 호출하거나 반복 이동하지 않는다.
- 나중에 설치 준비 이벤트가 오면 열린 안내에서 설치 버튼을 표시한다. 한 이벤트의 prompt는 한 번만 사용하고 준비·요청 중·요청 수락·실제 설치 완료를 구분한다. 요청 수락만으로 설치 완료로 표시하지 않는다.
- Threads/Barcelona·Android WebView를 포함한 환경 안내, iPhone의 Safari 메뉴 안내를 유지한다. UA로 모든 앱 브라우저를 완벽하게 식별한다고 가정하지 않으며 실제 설치 이벤트가 있으면 그것을 우선한다.
- 다른 브라우저의 저장·신청 기록이 자동 이전되지 않음을 안내한다. 저장소·백업·서비스워커·캐시·수집/블로그/Threads 운영 설정은 변경하지 않는다.

## 검증

- Node 56개, Python 89개 통과 (145개). 공유 취소/복사 권한 거부/설치 요청 중복·수락과 완료 구분·캐시 격리·기록 관리 회귀를 포함한다.
- 정적 빌드의 지원금 10,942개·적격 sitemap 11,050개 검사 통과. 새 JS/CSS 내용에 따라 기존 생성기가 자산 해시를 갱신한다.
- 320/390/1440px에서 실제 UI 모듈을 연 모의 환경으로 가로 넘침 없음. Android Threads 이동/복사 안내, 복사 거부 후 수동 선택, 늦게 도착한 설치 이벤트, Safari 안내, 외부 브라우저에서 안내 이어가기 및 URL 매개변수 정리를 확인했다.
- 브라우저 QA는 격리된 메모리 저장공간·클립보드·합성 설치 이벤트를 사용했다. 실제 Android Threads→Chrome 전환과 OS 홈 화면 설치 완료는 미확인이다. 실제 설치는 사용자가 해당 휴대폰에서 확인해야 한다.
- QA 파일은 생성 산출물의 로컬 검토 복사본에만 있고 커밋/공개 배포 입력에 포함하지 않는다. 공개 배포는 승인 범위와 CI를 확인한 뒤 기존 최신 정상 수집 세대 복원 workflow를 사용한다.

문제가 있으면 이 변경만 revert한다. 기존 앱 ID나 개인 기록을 초기화하거나 다른 프로젝트의 서비스워커·캐시를 삭제하지 않는다.
