## 동작

공개 빌드는 홈페이지, 지원사업 상세, 목록 및 가이드·안내 페이지에 공통 CSS와 지연 실행 JavaScript를 각각 한 번 넣는다. 페이지 깊이에 맞는 상대 경로와 기존 콘텐츠 해시 버전 처리를 사용한다. 오류 페이지와 오프라인 안내에는 넣지 않는다. 미리보기 빌드에는 통계 로더를 연결하지 않으며, 로더 자체도 운영 호스트와 `/supportpick/` 경로를 확인한다.

방문자가 페이지 하단에서 허용한 뒤에만 `https://wcs.pstatic.net/wcslog.js`를 불러오고, 로드가 완료되면 `wcs_add.wa`에 위 ID를 설정하여 `wcs_do()`를 문서당 한 번 호출한다. 필터, 저장 버튼 및 모달 조작을 추가 페이지뷰로 계산하지 않는다. 기본값과 거부 상태에서는 네이버 스크립트를 요청하지 않는다.

선택은 이 브라우저에서 기억한다. 저장 실패를 화면에서 안내하며, 허용 철회 시 저장된 거부 상태로 새로고침하여 이미 불러온 SDK도 종료한다. 다른 탭에서의 철회도 반영한다. SDK 연결 오류나 다른 ID와의 충돌은 기존 사이트 기능을 중단시키지 않는다. 기존 혜택·신청 메모와 수집·Threads 게시 일정은 변경하지 않는다.

## 검증

- Python 전체 검사와 JavaScript 기존 검사는 PR의 `Verify SupportPick release`에서 수행한다.
- `Content mobile readability check`에서 기존 화면 검사와 통계 브라우저 검사 8개를 실행한다.
- 통계 브라우저 검사는 네이버 SDK를 로컬 대역으로 대체하므로 실제 집계를 발생시키지 않는다.
- 허용·거부·철회, 중복 초기화, 저장공간 실패, SDK 오류, 타 사이트 경로 및 발급 ID 격리를 확인한다.
- 공개 빌드 검사는 생성된 페이지마다 버전이 붙은 두 로컬 자산이 한 번씩 연결되는지 확인한다.
- 실제 배포에서는 기존 승인된 스냅샷 배포 절차로 최신 검증 데이터와 현재 main을 확인한다.
- 코드의 `sent` 상태는 `wcs_do()` 호출 완료이며 네이버 보고서 반영까지 증명하는 값이 아니다. 실서비스 확인은 실제 요청의 `wa` 값과 네이버 실시간 보고서를 대조한다.
